# Creator Improve

Use this capability for a material user correction, demonstrated process/tool failure, reusable discovery, or project milestone/close. It is not a mandatory extra agent or a review after every message. Preserve the user's main task and budget.

Follow [the improvement cycle](references/improvement-cycle.md): identify evidence, distinguish project-only lessons from reusable changes, search existing lessons, make the smallest justified patch, validate it and save a compact result. A single concrete defect can justify a narrow fix; an untested idea stays a proposal. Do not invent a lesson just because a project ended.

The user authorizes small reversible improvements to this kit while work proceeds. Prepare major changes to workflow, approval boundaries, cost/dependencies or persisted-state compatibility for a scope decision. Kit maintenance does not authorize new production, paid calls, publication or changing a project's approved plan.

Keep shared records under improvements/ using templates/LESSON.md; keep niche settings in their own project. Use Git and relevant checks for traceability. Never modify unrelated project changes or silently switch instructions mid-task. Read only the affected skill and relevant evidence; do not reload the whole kit/history.

Return what changed, why, checks actually run and what remains unverified, then continue the original task. No recursive self-improvement loop or fabricated token savings. This skill runs when invoked/selected in an active session; it is not a background scheduler and cannot hot-reload other chats.
